### 数据库设计方案（已确认并落库）

**交付状态**：2026-11-15 用户批准按方案落库，三张业务表的以下字段、约束与正常操作流程已实现；环境和验证限制以上述实际记录为准。结果不确定或孤立文件的核对仍是受控人工处理要求，不是已实现的后台自动任务。

#### 1. 场景与范围

- 使用场景：本机单人 PDF 资料库，上传、列出、下载和删除文件。当前服务端固定身份为 `local-demo`，不是企业登录用户，也不是已实现的多部门权限系统。
- 输入：单个 PDF，原始文件大小为 5 至 10,485,760 字节；服务端检查文件名、类型、大小及 `%PDF-` 文件头。文件头检查不等于完整 PDF 结构校验或恶意文件检测。
- 输出：资料元数据、下载文件、去重提示与删除结果；“已保存”不表示解析完成或可问答。
- 数据边界：仅使用获准的无敏感演示资料；原始文件加密保存在仓库外，数据库保存元数据和存储定位键，不保存明文文件、密钥或绝对路径，不调用外部 AI。
- 权限边界：必须同时满足所属人匹配和显式可读 ACL；缺少 ACL 默认拒绝。用户身份只能由服务端提供，客户端不能指定或覆盖 `owner_id`、`subject_id`、`actor_id`。
- 当前资料量、并发和保留期限尚未确认，不作容量承诺；暂沿用最近 200 条列表及前端文件名筛选，不新增搜索系统、用户表、组织表、解析任务或向量表。

#### 2. 存储方案对比与推荐

| 维度 | A：三张元数据表 + 仓库外加密文件（推荐） | B：元数据表 + 数据库内加密文件 `bytea` |
| --- | --- | --- |
| 数据流 | 文件由现有本地适配器加密保存，`pg` 事务写元数据、ACL、审计 | 文件先加密，再与元数据一起写数据库事务 |
| 场景适配 | 贴合当前代码和单文件 10 MB 限制 | 适合更重视文件与记录单一事务一致性的场景 |
| 优点 | 复用现有存储接口，数据库不承载文件正文，后续可替换文件存储 | 文件与元数据可同事务提交，备份入口较集中 |
| 代价 | 文件系统和数据库无法原子提交，必须做失败补偿与核对；备份需同时覆盖两者 | 需改写存储适配器和上传事务，文件会增加数据库、WAL 和备份的数据量 |
| 安全 | 文件密钥独立于数据库；下载重新授权，存储键不返回前端 | 仍需独立密钥和下载授权；数据库权限泄漏可能暴露加密文件全集 |
| 开发维护与性能 | 少改动；读写延迟、并发和磁盘消耗待实测 | 改动更多；数据库写入和备份开销待实测 |
| 费用与部署 | 本机磁盘、数据库运行及双资源备份维护成本，未估价，不新增云资源 | 本机数据库容量及备份维护成本，未估价，不新增云资源 |
| 迁移退出 | 可通过存储接口搬迁文件并核对哈希，需协调元数据和文件 | 文件从数据库导出后核对哈希并切换适配器，需控制切换窗口 |
| 已有证据 | 本地 AES-256-GCM 适配器、参数化 SQL 和事务已通过本轮真实集成验证；容量性能未测 | 本项目尚无数据库文件存储实现，收益与开销未实测 |

**推荐**：选择 A，保留 `pg` 和现有文件存储接口，不安装 ORM 或引入新供应商。主要牺牲是双资源一致性和备份复杂度，不能宣称“数据库事务成功就解决所有文件一致性问题”。

**反转条件**：若必须保证文件与元数据的单一事务提交，且接受数据库容量、备份和接口改造代价，可重新选择 B。多用户、共享目录或远程部署会推翻本机固定身份的前提，须先重新设计认证、权限和存储边界。

#### 3. 表关系

业务表使用 `eap` schema：

- `documents`：每条记录对应一个上传的文件，软删除后保留元数据。
- `document_acl`：通过 `document_id` 关联文档，一份文档可有多条权限记录；本次仅创建所属人自己的可读记录，不实现共享。
- `audit_events`：通过 `document_id` 关联文档，追加记录首次保存与首次删除，禁止级联删除审计。

迁移工具另有 `eap_meta.migrations` 技术表，记录迁移文件名、校验和和执行时间；已在本轮创建，不属于业务表。旧 SQL 草稿包含的 `ingestion_jobs` 已从首次实际应用的迁移和仓储调用中移除，本轮未创建解析任务表。

#### 4. `documents`：文档主表

除 `deleted_at` 外，所有字段均为 `NOT NULL`。默认值不能替代约束。

| 字段 | PostgreSQL 类型 | 默认值与约束 | 业务含义 |
| --- | --- | --- | --- |
| `id` | `uuid` | 主键；服务端生成 UUID v4，无数据库默认值 | 文档标识，与现有文件命名及接口兼容；不作为访问凭证 |
| `owner_id` | `text` | 非空且去除首尾空白；本次服务端固定写 `local-demo` | 所属人稳定身份，不使用姓名 |
| `filename` | `text` | 长度 1～200，禁止路径分隔符和控制字符，PDF 扩展名；服务端统一规范化 | 上传时的展示名称；不用作磁盘路径，同名不同内容允许共存 |
| `storage_key` | `text` | 唯一，须为与 `id` 一致的 `<UUID>.pdf.enc` | 仓库外加密文件的相对定位键；不向前端暴露 |
| `size_bytes` | `integer` | 5～10,485,760 | 原始 PDF 字节数，不含加密封装开销 |
| `content_hash` | `text` | 64 位小写十六进制，SHA-256 | 对原始文件字节计算；用于内容去重，不是加密或权限凭证 |
| `source_type` | `text` | 默认 `pdf`，本次仅允许 `pdf` | 文件来源类型，不另设重复的 MIME 字段 |
| `classification` | `text` | 默认 `internal`，本次仅允许 `internal` | 当前仅内部演示资料；不声称已支持企业密级制度 |
| `external_allowed` | `boolean` | 默认 `false`，本次约束为 `false` | 外发关闭；后续不得仅靠修改此字段绕过授权 |
| `status` | `text` | 默认 `stored`，仅允许 `stored`、`deleted` | 已保存或已删除，不表示解析和问答能力 |
| `cleanup_pending` | `boolean` | 默认 `false`；为真时必须为 `deleted` | 已停用但加密文件清理尚未确认完成 |
| `created_at` | `timestamptz` | 默认 `now()`，不可随删除或重传修改 | 元数据首次写入时间，前端按本地时区展示 |
| `updated_at` | `timestamptz` | 初始默认 `now()`，状态或清理结果变化时由仓储代码更新 | 最近一次持久化变更时间，不在每次读取时更新 |
| `deleted_at` | `timestamptz` | 默认 `NULL`；`stored` 时为空，`deleted` 时非空 | 首次软删除时间，清理重试不覆盖 |

时间约束：`updated_at >= created_at`；非空的 `deleted_at` 应介于二者之间。除生命周期字段外，不提供修改文件内容、所属人或存储键的接口。

索引：

- 主键和 `storage_key` 唯一约束自带索引，不重复创建。
- 部分唯一索引 `(owner_id, content_hash) WHERE status = 'stored'`：同一所属人相同内容最多一条有效记录，防止并发上传重复入库；不同所属人不跨权限去重。
- 列表索引 `(owner_id, created_at DESC, id DESC)`：支持所属人过滤及稳定倒序，列表只包含 `stored` 和 `deleted AND cleanup_pending`，最多 200 条。
- 清理索引 `(updated_at, id) WHERE cleanup_pending = true`：用于定位待清理记录；索引本身不代表已有自动清理服务。

保留 UUID v4 是为了兼容现有代码、不引入扩展；随机主键的大表索引局部性弱于顺序主键，当前规模未知，后续凭测量结果决定是否更换。

#### 5. `document_acl`：显式访问权限表

所有字段均为 `NOT NULL`。

| 字段 | PostgreSQL 类型 | 默认值与约束 | 业务含义 |
| --- | --- | --- | --- |
| `document_id` | `uuid` | 外键指向 `documents.id`，物理删除采用 `RESTRICT` | 权限对应的文档 |
| `subject_id` | `text` | 非空且去除首尾空白，与服务端身份规则一致 | 获授权的稳定身份，本次等于 `owner_id` |
| `can_read` | `boolean` | 默认 `false` | 只有显式为真才能列出或下载 |

联合主键 `(document_id, subject_id)`，同时覆盖按文档查权限的索引需求。

本次上传在同一数据库事务中插入所属人 ACL，`can_read = true`。列表和下载必须同时验证 `owner_id = 当前身份`、对应 ACL 为真；删除也要求所属人匹配和可读 ACL，不开放委托删除。软删除后 ACL 保留，但文档状态立即阻断下载。缺失 ACL 时不因所属人匹配而自动放行。

本次无用户表外键，也无共享、撤销或授权管理接口；未来接入企业身份时需核对身份映射。应用层校验不是数据库行级隔离，本机同源检查也不是登录认证，不据此开放多用户或公网。

#### 6. `audit_events`：文档操作审计表

所有字段均为 `NOT NULL`。

| 字段 | PostgreSQL 类型 | 默认值与约束 | 业务含义 |
| --- | --- | --- | --- |
| `id` | `uuid` | 主键；服务端生成 UUID v4 | 审计事件标识 |
| `format_version` | `integer` | 默认 `1`，本次仅允许 `1` | 事件格式版本 |
| `event_type` | `text` | 仅允许 `document.uploaded`、`document.deleted` | 首次保存成功、首次逻辑删除成功 |
| `actor_id` | `text` | 非空且去除首尾空白，服务端写入 | 执行人稳定身份，本次为 `local-demo` |
| `document_id` | `uuid` | 外键指向 `documents.id`，物理删除采用 `RESTRICT` | 关联文档，不存文件正文或原始文件名 |
| `created_at` | `timestamptz` | 默认 `now()` | 事件写入时间 |

索引 `(document_id, created_at, id)` 支持按文档追溯；唯一约束 `(document_id, event_type)` 保证每份文档只有一次上传和一次删除事件。重复上传复用原记录、重复删除和重试清理均不新增这两类事件。

这是文档生命周期审计，不是全部会话、失败尝试或下载访问日志。若需要这些日志，应单独确认事件范围，不能宣称已完整审计。审计不记录密钥、连接串、文件正文、内容哈希或原始错误载荷。

应用角色仅可 `INSERT`，不得 `UPDATE`、`DELETE`、`TRUNCATE`；审计查询使用另行授权的只读角色。追加限制不等于对数据库管理员防篡改，未实现外部防篡改归档。

#### 7. 操作流程与一致性

**上传**

1. 服务端校验请求和 PDF，流式计算原始内容哈希并加密写入临时文件；写完后同步文件并改名为最终存储键。
2. 开启数据库事务，写入 `documents`、所属人 ACL 和上传审计事件；任一写入失败则整组回滚。不写解析任务，不使用 `queued`。
3. 同所属人的有效内容哈希冲突时，查询其有权读取的已有记录，复用其 ID、原文件名和首次上传时间。新上传的临时副本在事务结束后清理，不另写上传审计；无 ACL 不返回已有文档信息。
4. 只有数据库提交确认成功后才返回保存成功。上传进度 100%、客户端取消、超时或断线都不证明服务器未保存，界面须刷新列表确认。

**失败补偿与结果不确定**

- 文件校验或加密失败：清理临时文件，不写元数据。
- 数据库确认未提交：尝试删除本次新生成的加密文件；删除失败或进程崩溃可能留下孤立文件，不能静默宣称完全回滚。
- `COMMIT` 返回结果不确定：保留加密文件，不先删除。恢复连接后按此次文档 ID 与存储键核对；已提交则保留，确认未提交才清理。无法核对则继续提示结果待确认。
- 去重副本清理失败：已有记录仍有效，不能把已有文档删掉；界面应区分“已有资料”与“副本待清理”，不可误报没有保存。
- 本轮正常与回滚流程已核对临时文件和孤立文件，缺失文件分支通过真实集成测试。发生异常后的人工核对须先停止新上传并等待在途请求结束，再以文件名中的 UUID 查询数据库状态和存储键；连接不可用或提交结果未明确时保留文件，不按一次查询缺失就删除文件。任何手动删除需另行确认。本次未实现定时任务，不保证自动修复孤立文件。缺失文件的下载返回存储故障，不能返回虚假文件。

**列表与下载**

1. 列表按当前身份与 ACL 过滤，不向前端返回所属人、存储键和内容哈希；只返回页面必需的字段。
2. 下载按文档 ID 检查身份、ACL 和 `stored` 状态，读取并验证加密文件，再次核对访问资格后返回。
3. 二次检查减小并发删除暴露窗口，但不能撤回已读取或开始传输的字节；删除承诺是阻断后续授权的访问，不是远程擦除已有副本。

**删除**

1. 数据库事务内锁定有权操作的文档；首次删除将 `status` 改为 `deleted`，设置 `deleted_at`、`updated_at` 和 `cleanup_pending = true`，同时写入一次删除审计。
2. 提交确认后才物理清理文件。提交结果不确定时暂不清理，先核对状态；不能让仍为 `stored` 的记录失去文件。
3. 文件清理成功或确认文件已不存在后，更新 `cleanup_pending = false` 和 `updated_at`，列表不再显示该记录；数据库和审计记录保留。
4. 清理失败时保持 `deleted` 和 `cleanup_pending = true`，下载仍被拒绝，列表显示“已停用，待清理”；重复删除只重试清理，不改首次删除时间，也不重复写删除审计。
5. 同内容在软删除后允许重新上传，使用新的文档 ID 和独立存储键，旧清理不会删除新文件。本次不提供撤销删除、回收站或恢复文件功能。

#### 9. 验证方式

先写失败测试，再修改实现；不使用生产数据或未经授权的敏感 PDF，不安装新依赖，不承诺未经测量的性能。

- 字段约束：非法名称、大小、哈希、状态、外发标志和时间组合被拒绝。
- 上传事务：三表同时写入或回滚；ACL、审计写入失败时不产生半条有效资料。
- 并发与去重：同所属人同内容只保留一条有效记录；同名不同内容允许共存；其他所属人或缺少 ACL 的记录不会泄漏。
- 删除与重试：文件立即不可访问；清理失败可重试，首次删除时间和审计事件不重复；删除后重传不受旧清理影响。
- 故障核对：数据库不可用、提交结果不确定、文件缺失、清理失败以及连接中断均不误报成功；核对流程不删除有效文件。
- 权限验证：应用角色不能改写审计或执行 DDL；列表、下载和删除缺少 ACL 均拒绝。
- 真实集成：在专用测试库使用合法小 PDF 测试上传、列表、下载字节一致、重传去重、删除及失败分支，然后运行单元测试、类型检查、lint 和构建。性能、容量与备份恢复未验证时继续标注待测。
