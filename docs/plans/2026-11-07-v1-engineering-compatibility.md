## 1. 上传和资料列表（下一步）

**做什么**：让你能真正把 PDF 放进系统并管理它。

- [ ] 1.1 做资料页面：上传入口、资料列表和空列表提示。
- [ ] 1.2 接通真实上传和保存，显示文件名、上传时间和“已保存 / 待处理”状态。
- [ ] 1.3 处理重复上传、非法文件、上传失败和删除，提供清楚提示。
- [ ] 1.4 验证上传后刷新或重启资料仍在，删除后不可读取。

**完成后**：你能上传 PDF、看到列表并删除文件。此时还不能提问，也不把“上传成功”显示成“资料已可问答”。
**技术配套**：为了保存资料，接入数据库和本地受控文件存储；登记文件归属与待处理任务，保护上传和删除接口。数据库验证就在这个功能内完成，不单独再做一轮架构搭建。

## 2. 读取并保存资料

**做什么**：让系统读取 PDF 内容，为后面的问答做好准备。

- [ ] 2.1 提取每一页的文字，保留文件名和从 1 开始的物理页码。
- [ ] 2.2 提供文字预览和真实处理状态；扫描页、损坏或加密文件有明确提示。
- [ ] 2.3 将文字分段并建立可搜索内容，处理任务在重启后能恢复。
- [ ] 2.4 验证文字和页码正确；只有搜索内容准备完成才显示“可问答”。

**完成后**：你能查看提取的文字，知道哪些资料已准备好、哪些处理失败或有缺失。
**技术配套**：按需接入 PDF 解析、本地中文向量模型、分词和计算进程；在对应功能中验证兼容性和搜索效果。删除或重试不能让已删除资料重新出现。

## 3. 提问和查看来源

**做什么**：让你针对已处理的资料提问，并能核对答案依据。

- [ ] 3.1 做问答页面，选择资料范围并输入问题。
- [ ] 3.2 搜索相关内容，接入获准的 DeepSeek 调用，根据资料生成回答。
- [ ] 3.3 展示答案、文件名、页码和原文；点击引用可以核对来源。
- [ ] 3.4 无依据、来源冲突或模型失败时明确说明，不编造答案；已删除资料的旧引用不可继续读取。

**完成后**：你能完成“提问 → 看答案 → 核对原文”。
**技术配套**：接通关键词与向量混合搜索、外发检查、模型网关、引用校验和脱敏记录；每次读取都检查当前资料权限。

## 4. 完整试用检查

**做什么**：确认这套功能能从头到尾实际使用。

- [ ] 4.1 用 3 份无敏感 PDF 和约 10 个问题，逐题核对答案、页码和原文。
- [ ] 4.2 检查重复上传、扫描页、处理失败、重启恢复、处理中删除、无答案和模型失败。
- [ ] 4.3 检查无权限访问、敏感内容外发阻断和日志脱敏，补齐启动、停止及本地数据导出恢复说明。

**完成后**：交付可本机使用的 PDF 问答首版。真实数据库、本地模型和 API 必须分别实测，不能用模拟成功代替；仍不代表企业生产上线。

## 每一步共同遵守

- 先写测试，再实现，并通过真实操作检查；只有完成并验证后才勾选。
- 仅本机单人、无敏感演示资料；不开放公网、不接飞书、不做 OCR、业务办理或云部署。
- 原文件和模型放在代码仓库之外，密钥只保存在服务端，日志脱敏，缺少权限默认拒绝。
- 数据库、角色、扩展和新依赖的操作范围在对应功能开始前用简短说明确认；不影响已有数据库或全局环境。
- 模型下载、API 外发和费用单独确认；精简计划不等于取消安全、数据保护或真实验证。
- 技术要求和预计代码位置见 [V1 技术架构方案](../architecture/evolution-plan.md#8-v1-技术架构方案)，版本目标见 [迭代路线](iteration-roadmap.md)；只创建当次功能需要的文件。
