# 企业 Agent 平台总体架构

**核心要点：** 第一版只实现 PDF 入库与问答；企业能力逐步叠加，最终架构不等于首版实施清单。当前全部业务能力尚未实现。

更新日期：2026-11-06。目标与交付范围以 [迭代路线](../plans/iteration-roadmap.md) 为准，技术方案、升级选择与迁移见 [架构升级计划](evolution-plan.md)。

## 1. 第一版实际需要什么

```text
浏览器：资料页 + 问答页
        ↕
TypeScript 应用
├── PDF 导入：按页提取、分块、状态与删除
├── 检索：关键词 + 向量，去重后 RRF 融合
├── 问答：必要证据、无依据提示、页码引用
├── 策略：演示身份、文件可见范围、外发阻断
└── 模型网关：DeepSeek、超时与脱敏记录
        ↕
PostgreSQL + pgvector / 本地中文 Embedding / 受控文件目录
```

V1 先使用 3 份无敏感 PDF，只支持文字型 PDF；不开发飞书登录、同步任务平台、实时工具或完整管理后台。Next.js 是候选框架，未锁定。数据库与向量模型独立运行，应用内业务保持模块边界，不默认微服务。

## 2. 后续能力怎样加入

| 层次 | V1 | 后续增加 |
| --- | --- | --- |
| 资料入口 | PDF 上传 | V2 飞书；其他格式按需求增加 |
| 文档处理 | 文字提取、分块、版本和页码 | 同步状态、结构定位、发布治理；OCR 按实际需求 |
| 身份与权限 | 固定演示身份、显式文件可见范围 | V2 飞书身份与有效源权限，V6 多域隔离 |
| 检索与模型 | PostgreSQL + pgvector、RRF、本地向量、DeepSeek 网关 | 先调优现有组件，有瓶颈才比较专用搜索和重排序 |
| Agent | 基于资料的问答 | V3 Skill / References、受限只读工具；V5 审批后操作 |
| 运营治理 | 基本状态、失败提示、脱敏记录和功能检查 | 真实资料前必要审计 / 备份；V4 完整生产治理 |
| 部署 | 本机单人 | 获准受控试点，V4 境内阿里云；V6 按需扩容 |

远程真实试点不能继续使用本地演示身份或公开文件目录；其所需网络、安全与运维能力必须提前实施。

## 3. 企业目标架构

```text
PDF / 飞书 / 后续获准资料入口
        ↓
连接器 → 统一文档 → 解析 / 分块 / 索引 / 生命周期
        ↓
授权检索 → Agent 编排 → Model Gateway → DeepSeek
                 ↓
         Skill + References + 受限工具
                 ↓
         企业 API / MCP：先只读，后审批写入
                 ↓
         答案、引用、查询结果或办理状态

横切保障：可信身份、权限、密级、脱敏审计、评测、监控、备份恢复
受控数据：PostgreSQL + pgvector、受控 Embedding、文件存储及后续私有 OSS
```

这些是职责，不必各自独立部署。可视化见 [阶段架构图](project-architecture.md)；具体资源、部署拆分与供应商能力需另行验证确认。

## 4. 核心边界

- **访问**：检索前过滤权限，关键词和向量两路一致；文件读取与工具调用重新授权。缺失权限默认拒绝。
- **有效性**：来源、版本、删除和停用状态决定证据是否可用；有阅读权限不意味着旧内容应参与回答。
- **外发**：有阅读权限不等于能发给模型，严格受限内容禁止外发；本地应用调用 DeepSeek 仍跨出本地边界。
- **流程**：Skill 规定行为，References 提供受控资料，工具提供实时证据；Memory 不绕过当前授权。
- **操作**：解释流程不等于获得代办许可，V3 保持只读，V5 操作需确认、审批及幂等。

## 5. 保持简单的原则

不以完整目标架构阻挡 V1；不以演示成功宣称企业可用。V1 用少量 PDF 检查主链路，V2 / V3 按试点积累真实问题，V4 完成生产验收。安全与真实资料授权按启用条件前置，专用搜索、微服务、图谱和多 Agent 只按实际瓶颈评估。
