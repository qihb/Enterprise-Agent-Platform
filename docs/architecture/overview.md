# 企业 Agent 平台总体架构

## 1. 目标

为集团员工提供安全、可追溯的知识问答、流程辅助和业务工具调用能力。平台不把所有数据简单转换为向量，而是根据数据类型选择文件检索、混合 RAG、结构化查询或 API/MCP。

## 2. 分层架构

```text
企业数据源
├── 飞书 / 企业微信 / OA
├── Wiki / 网盘 / Git
├── ERP / CRM / HR
├── 工单与审批系统
└── PDF / Word / Excel / Markdown
        ↓
连接器与同步层
        ↓
解析、清洗、版本、权限映射
        ↓
知识注册中心
        ↓
检索与查询层
├── 关键词检索
├── 向量检索
├── 元数据与权限过滤
├── 重排序与上下文压缩
└── 结构化查询 / MCP 查询
        ↓
Agent 编排层
├── Skill：规定工作流程
├── References：领域规范与操作资料
├── MCP：外部系统和业务工具
├── Memory：用户与任务上下文
└── Policy：权限、审批和风险控制
        ↓
应用层
├── 企业统一助手
├── 领域 Agent
├── 流程办理
└── 数据分析
```

## 3. 核心边界

- 权限过滤必须发生在检索前，并在工具调用前再次校验。
- 实时业务数据优先通过 API/MCP 查询，不以静态文档替代。
- Skill 负责流程和行为约束，知识库负责事实资料，Memory 不承载公共制度。
- 所有回答应尽量返回来源、版本、生效时间和原文链接。
- 高风险操作需要人工确认、审批或受限工具权限。

## 4. 首期范围建议

先选择一个边界清晰且只读的领域，例如 IT 服务台、HR 制度或销售产品资料，覆盖 50 到 300 份核心资料和 20 到 50 名真实用户。首期目标是验证正确性、权限安全、引用质量和用户采纳率，而不是一次覆盖全集团。
