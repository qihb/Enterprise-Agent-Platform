# 架构决策记录

## ADR-001：采用平台与业务域分层

**状态**：已提议

集团级平台提供连接器、权限、检索、审计、评测和 Agent 运行能力；人力、财务、法务、IT、销售等业务域分别维护自己的知识范围、负责人、权限和更新周期。

**原因**：避免建设一个无法治理的“全集团大知识库”，并让业务专家对知识正确性负责。

## ADR-002：采用混合检索，而非单一向量检索

**状态**：已提议

检索层组合关键词检索、向量检索、元数据过滤和重排序。需要实时数据时，转为结构化查询或 MCP/API 调用。

**原因**：精确词、编号、函数名和制度名称适合关键词；同义表达和模糊问题适合语义检索；实时数据不能依赖静态索引。

## ADR-003：优先采用 Skill + References 组织领域流程

**状态**：已提议

对于流程规范、操作手册和小型高价值资料，使用 Skill 引导 Agent 渐进式读取 References；对于大规模或外部知识，再通过统一检索服务或 MCP 调用 RAG。

**原因**：保留目录、文件名和章节关系，同时保留 RAG 在大规模检索场景中的优势。

## ADR-004：权限先于检索

**状态**：已提议

所有索引项必须携带来源权限信息。检索前按用户身份、组织、角色、密级和文档 ACL 过滤；工具调用前进行独立授权。

**原因**：集团 Agent 的首要生产风险是越权泄露，而不是单纯的回答质量下降。

## ADR-005：首期试点选择 IT 服务台只读场景

**状态**：已接受

首期选择 IT 服务台作为试点业务域，优先覆盖以下场景：

- 制度、操作资料和服务目录问答
- 常见故障与问题排查
- 流程办理条件、材料、步骤和责任人说明
- 业务人员对流程不清和数据异常的只读咨询与初步诊断

首期不直接修改业务数据、不自动提交工单以外的业务操作；涉及数据修复、权限变更或其他写入行为时，转人工或进入后续审批流程。

**原因**：IT 服务台资料边界相对清晰、问题频率高，适合验证混合检索、引用溯源、权限过滤、拒答和人工转交。将数据问题限定为只读诊断，可以控制首期业务风险，同时保留后续接入实时 API/MCP 的空间。

## ADR-006：首期采用飞书统一身份与文件级权限

**状态**：已接受

首期用户登录、用户身份和组织架构以飞书为主要来源；知识资料先继承源系统的文件级 ACL。平台在检索前按用户身份、部门、群组和文件 ACL 过滤，暂不实现段落级权限。

**原因**：复用现有组织和群组关系，减少自建账号体系和复杂权限同步的范围。文件级权限足以支持 IT 服务台 MVP，段落级权限留待出现明确业务需求后再评估。

## ADR-007：首期采用飞书与本地文件的定时增量同步

**状态**：已接受

首期知识源包括飞书云文档/知识库和本地受控文件（PDF、Word、Markdown、Excel 等）。同步采用定时增量方式，依据更新时间、版本号或内容哈希识别新增、变更和删除；首期暂不接入 ITSM/工单知识库。

**原因**：优先验证文档解析、版本、文件级权限、引用和过期处理，降低对多个业务系统 API 与事件接口的依赖。定时增量同步能够满足 MVP 的时效性要求，并为后续事件实时同步保留接口。

## ADR-008：模型按数据敏感级别分流

**状态**：已接受

首期通过统一 Model Gateway 接入企业云 API。普通 IT 制度和操作资料可调用符合企业合规要求的境内模型服务；包含个人信息、账号信息、内部网络配置、密钥或详细日志等敏感内容时，先执行脱敏，必要时限制在企业私有网络内处理。

Model Gateway 负责数据分级判断、脱敏、模型路由、调用审计、成本统计、超时降级和供应商策略校验。原始知识库不直接提供给模型，只向模型发送经过权限过滤的必要上下文。

**原因**：兼顾首期交付速度、模型效果和数据控制能力，避免所有数据一律发送到外部服务，也避免 MVP 一开始承担完整私有化模型的 GPU 与运维成本。

## ADR-009：采用四级数据分级并阻断高敏内容外发

**状态**：已接受

首期采用四级数据分级：公开、内部、敏感、严格受限。密钥、密码、令牌、个人信息和内部网络配置默认归入严格受限范围，禁止发送给外部模型服务；系统应阻断请求，记录脱敏后的审计事件，并转人工或引导用户使用受控渠道。

**原因**：让模型路由具备明确、可测试的策略边界，优先防止凭据和个人信息泄露。自动脱敏作为后续增强能力，不作为首期放行高敏内容的依据。
