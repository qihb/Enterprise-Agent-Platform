# 架构决策记录

## ADR-001：采用平台与业务域分层

**状态**：已提议

集团级平台提供连接器、权限、检索、审计、评测和 Agent 运行能力；人力、财务、法务、IT、销售等业务域分别维护自己的知识范围、负责人、权限和更新周期。

**原因**：避免建设一个无法治理的“全集团大知识库”，并让业务专家对知识正确性负责。

## ADR-002：采用混合检索，而非单一向量检索

**状态**：已提议

检索层组合关键词检索、向量检索、元数据过滤和重排序。需要实时数据时，转为结构化查询或 MCP/API 调用。

**原因**：精确词、编号、函数名和制度名称适合关键词；同义表达和模糊问题适合语义检索；实时数据不能依赖静态索引。

## ADR-003：优先采用 Skill + References 组织领域流程

**状态**：已提议

对于流程规范、操作手册和小型高价值资料，使用 Skill 引导 Agent 渐进式读取 References；对于大规模或外部知识，再通过统一检索服务或 MCP 调用 RAG。

**原因**：保留目录、文件名和章节关系，同时保留 RAG 在大规模检索场景中的优势。

## ADR-004：权限先于检索

**状态**：已提议

所有索引项必须携带来源权限信息。检索前按用户身份、组织、角色、密级和文档 ACL 过滤；工具调用前进行独立授权。

**原因**：集团 Agent 的首要生产风险是越权泄露，而不是单纯的回答质量下降。
