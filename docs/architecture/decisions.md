# 架构决策记录

## ADR-001：采用平台与业务域分层

**状态**：已提议

集团级平台提供连接器、权限、检索、审计、评测和 Agent 运行能力；人力、财务、法务、IT、销售等业务域分别维护自己的知识范围、负责人、权限和更新周期。

**原因**：避免建设一个无法治理的“全集团大知识库”，并让业务专家对知识正确性负责。

## ADR-002：采用混合检索，而非单一向量检索

**状态**：已提议

检索层组合关键词检索、向量检索、元数据过滤和重排序。需要实时数据时，转为结构化查询或 MCP/API 调用。

**原因**：精确词、编号、函数名和制度名称适合关键词；同义表达和模糊问题适合语义检索；实时数据不能依赖静态索引。

## ADR-003：优先采用 Skill + References 组织领域流程

**状态**：已提议

对于流程规范、操作手册和小型高价值资料，使用 Skill 引导 Agent 渐进式读取 References；对于大规模或外部知识，再通过统一检索服务或 MCP 调用 RAG。

**原因**：保留目录、文件名和章节关系，同时保留 RAG 在大规模检索场景中的优势。

## ADR-004：权限先于检索

**状态**：已提议

所有索引项必须携带来源权限信息。检索前按用户身份、组织、角色、密级和文档 ACL 过滤；工具调用前进行独立授权。

**原因**：集团 Agent 的首要生产风险是越权泄露，而不是单纯的回答质量下降。

## ADR-005：首期试点选择 IT 服务台只读场景

**状态**：已接受

首期选择 IT 服务台作为试点业务域，优先覆盖以下场景：

- 制度、操作资料和服务目录问答
- 常见故障与问题排查
- 流程办理条件、材料、步骤和责任人说明
- 业务人员对流程不清和数据异常的只读咨询与初步诊断

首期不直接修改业务数据、不自动提交工单以外的业务操作；涉及数据修复、权限变更或其他写入行为时，转人工或进入后续审批流程。

**原因**：IT 服务台资料边界相对清晰、问题频率高，适合验证混合检索、引用溯源、权限过滤、拒答和人工转交。将数据问题限定为只读诊断，可以控制首期业务风险，同时保留后续接入实时 API/MCP 的空间。

## ADR-006：首期采用飞书统一身份与文件级权限

**状态**：已接受

首期用户登录、用户身份和组织架构以飞书为主要来源；知识资料先继承源系统的文件级 ACL。平台在检索前按用户身份、部门、群组和文件 ACL 过滤，暂不实现段落级权限。

**原因**：复用现有组织和群组关系，减少自建账号体系和复杂权限同步的范围。文件级权限足以支持 IT 服务台 MVP，段落级权限留待出现明确业务需求后再评估。

## ADR-007：首期采用飞书与本地文件的定时增量同步

**状态**：已接受

首期知识源包括飞书云文档/知识库和本地受控文件（PDF、Word、Markdown、Excel 等）。同步采用定时增量方式，依据更新时间、版本号或内容哈希识别新增、变更和删除；首期暂不接入 ITSM/工单知识库。

**原因**：优先验证文档解析、版本、文件级权限、引用和过期处理，降低对多个业务系统 API 与事件接口的依赖。定时增量同步能够满足 MVP 的时效性要求，并为后续事件实时同步保留接口。

## ADR-008：模型按数据敏感级别分流

**状态**：已接受

首期通过统一 Model Gateway 接入企业云 API。普通 IT 制度和操作资料可调用符合企业合规要求的境内模型服务；包含个人信息、账号信息、内部网络配置、密钥或详细日志等敏感内容时，先执行脱敏，必要时限制在企业私有网络内处理。

Model Gateway 负责数据分级判断、脱敏、模型路由、调用审计、成本统计、超时降级和供应商策略校验。原始知识库不直接提供给模型，只向模型发送经过权限过滤的必要上下文。

**原因**：兼顾首期交付速度、模型效果和数据控制能力，避免所有数据一律发送到外部服务，也避免 MVP 一开始承担完整私有化模型的 GPU 与运维成本。

## ADR-009：采用四级数据分级并阻断高敏内容外发

**状态**：已接受

首期采用四级数据分级：公开、内部、敏感、严格受限。密钥、密码、令牌、个人信息和内部网络配置默认归入严格受限范围，禁止发送给外部模型服务；系统应阻断请求，记录脱敏后的审计事件，并转人工或引导用户使用受控渠道。

**原因**：让模型路由具备明确、可测试的策略边界，优先防止凭据和个人信息泄露。自动脱敏作为后续增强能力，不作为首期放行高敏内容的依据。

## ADR-010：先本地验证，后续部署到境内阿里云

**状态**：已接受

首期在本地完成开发、测试和 MVP 验证，后续部署目标为境内阿里云。应用配置应区分本地与云端环境，不将云端凭据或资源地址写死在代码中。

境内阿里云的具体地域、计算资源、网络边界、备份和审计保留周期仍需在生产部署前确认。本地验证通过不代表已经具备生产上线条件。

**原因**：先验证问答、权限和引用能力，再落实云端资源与运维方案，控制首期成本和实施范围。

## ADR-011：问答模型使用 DeepSeek API

**状态**：已接受

首期问答模型通过统一 Model Gateway 调用 DeepSeek API；接入地址、模型标识和凭据通过环境配置提供，凭据不得写入版本库、请求日志或审计日志。

本地运行不意味着数据不外发：实际调用 DeepSeek API 时仍属于外部模型调用，必须遵守 ADR-009 的严格受限内容阻断规则。联调先使用公开或合成测试资料，真实企业资料的使用须经过授权及数据合规确认；应用部署在境内阿里云也不自动证明模型服务的数据驻留和保留政策符合企业要求。

此决策仅确定问答生成模型，不默认 DeepSeek API 同时提供 Embedding 或重排序服务；首期相关方案见 ADR-014。

**原因**：采用用户指定的模型服务，并通过网关保留统一策略校验、超时处理、调用审计和后续替换能力。

## ADR-012：首期检索使用 PostgreSQL + pgvector

**状态**：已接受

PostgreSQL 保存知识元数据、版本、组织身份与文件 ACL，同时承载关键词全文索引；pgvector 保存和查询文档分块向量。首期不额外部署独立搜索引擎或向量数据库。

中文关键词检索采用应用侧分词后写入 PostgreSQL 全文索引的方式，查询侧使用一致的分词规则，并保留制度编号、错误码和英文产品名称等精确词。不得将 PostgreSQL 默认全文解析直接等同于可靠的中文分词；具体分词器在阶段 1.4 通过评测确定。

关键词与向量两路查询都必须在数据库查询阶段应用文件 ACL、业务域、密级和有效版本约束，不允许先全库召回再在应用层删除未授权结果。权限信息缺失或失效的文档默认不可检索；本地数据库默认不向公网开放。

**原因**：首期资料规模有限，统一存储可以减少运维组件，并便于保持权限、版本与索引一致性。此方案仍需通过中文召回和权限回归验证，不代表已经满足集团生产容量要求。

## ADR-013：文件采用本地受控存储与 OSS 适配器

**状态**：已接受

本地验证阶段将原始文件保存到受控目录，数据库只登记文件标识、内容哈希、版本和存储引用。文件通过统一存储接口读写，后续增加阿里云 OSS 适配器，不让业务逻辑依赖本地绝对路径或 OSS 地址。

运行时文件、备份和密钥不进入 Git；文件下载须重新校验当前用户权限，不能将受控目录直接映射为公开静态资源。导入路径须限制在受控根目录内，防止路径穿越。

真实企业资料启用前须落实本地静态加密、密钥与数据分离、访问控制及备份恢复验证。云端使用私有 OSS Bucket，并在上线前确认加密、生命周期和备份策略；存储适配不等同于审计同步适配，两者分别实现。

**原因**：本地验证无需预先创建云资源，同时保留向 OSS 迁移的边界，并满足本地加密存储与权限控制要求。

## ADR-014：本地中文 Embedding 与 RRF 排序融合

**状态**：已接受

首期 Embedding 在本地受控环境运行，通过可替换的服务接口供 TypeScript 应用调用；后续迁移到境内阿里云的受控网络，不调用未经批准的外部向量服务。初始验证候选为 `BAAI/bge-small-zh-v1.5`，具体模型修订、运行组件和资源配置在阶段 1.4 验证后锁定。

入库和查询必须使用一致的模型版本、向量维度、归一化规则及各自的输入处理约定，并记录模型指纹。更换模型时重新生成索引，不混用不同模型产生的向量。本地计算向量也不代表可以绕过资料读取权限。

关键词与向量召回先按分块标识去重，再用 Reciprocal Rank Fusion（RRF）融合两路排名；首期不部署独立神经重排序模型。RRF 属于排名融合而非语义重排序，只有评测显示融合效果不足时，再评估独立重排序服务。

**原因**：避免将企业文档发送给额外的外部模型服务，并减少首期模型组件。候选模型的中文效果、CPU 延迟、内存占用和许可条件仍需验证，不能据此承诺生产性能。

## 生产部署前待确认项

- DeepSeek API 的接入渠道、数据驻留、保留政策和企业合规要求
- 境内阿里云的具体地域、计算资源、网络边界、备份和审计保留周期
- 云端 PostgreSQL 对 pgvector 的版本支持、容量与权限隔离验证

## 实现阶段待验证项

- 阶段 1.4：中文分词器、Embedding 模型修订与运行组件、RRF 参数和中文混合召回效果
- 阶段 1.2～1.3：本地文件加密、受控下载、删除与版本同步、缺失 ACL 时默认拒绝
- 阶段 1.5：DeepSeek 网关的高敏阻断、审计脱敏、超时降级和引用验证
