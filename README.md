# Enterprise Agent Platform

集团级 Agent 知识与工具访问平台的架构与实施项目。

## 项目目标

面向约 4000 人的集团组织，建设一套可治理、可追溯、可扩展的企业 Agent 平台：

- 用 Skill 定义 Agent 的工作流程；
- 用 References 保存结构化的领域资料；
- 用混合检索访问大规模知识；
- 用 MCP 访问企业系统和业务工具；
- 用统一权限、审计和评测保障生产可用性。

## 版本路线

| 版本 | 目标 | 主要交付 |
| --- | --- | --- |
| V1 | PDF 问答本地版 | 上传、入库、提问、答案、页码和原文 |
| V2 | 多入口知识库 | 飞书登录、文档接入、增量同步和真实权限 |
| V3 | 只读业务 Agent | Skill 流程、References、获准实时只读查询 |
| V4 | 企业生产版 | 受控云部署、审计、备份恢复、监控、质量与成本治理 |
| V5 | 受控业务办理 | 用户确认、审批、低风险操作、幂等与人工接管 |
| V6 | 集团扩展版 | 多业务域与子公司隔离，按实际瓶颈扩容 |

V4 是企业级知识与只读 Agent 的生产基线。V5 / V6 按业务需要扩展，不要求提前完成；远程试点所需的安全和运维能力必须提前落实。

## 当前阶段

目前只有设计文档，没有业务代码，也未验证所选组件。下一步是确认并实现 V1。

V1 先用 3 份无敏感演示 PDF 和约 10 个基于资料的问题跑通主链路，仅供本机单人使用。真实资料、多用户试点和生产服务分别按后续版本验证，不能把本地演示当成企业上线。

## 技术路线

首版采用 TypeScript 全栈路线，先在本地验证，后续部署到境内阿里云：

- 问答：DeepSeek API，经 Model Gateway 执行策略校验与调用管理。
- 检索：PostgreSQL + pgvector，应用侧中文分词与向量召回后使用 RRF 排序融合。
- 向量生成：本地中文 Embedding，首期不部署独立语义重排序模型。
- 文件：本地受控存储，后续通过适配器接入阿里云 OSS。

前后端框架在 V1 工程初始化前确认，Next.js 当前只是候选。中文召回效果和本地模型资源需求仍需验证；本地运行也不免除 DeepSeek API 外发数据的合规要求，严格受限内容禁止发送给外部模型。

## 协作约定

核心 AI 规范：[agent.md](agent.md)。重要技术决策必须先分析场景，提供方案优劣、阶段适用性、验证证据与迁移代价的对比，再由用户确认；长期架构演进按实际瓶颈和复审条件推进，不默认提前升级。

本项目遵循“先确认计划，再按指定阶段执行”的协作方式。每完成一个阶段，都要同步更新计划文档、验证结果和待办事项。
