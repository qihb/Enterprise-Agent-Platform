# Enterprise Agent Platform

集团级 Agent 知识与工具访问平台的架构与实施项目。

## 项目目标

面向约 4000 人的集团组织，建设一套可治理、可追溯、可扩展的企业 Agent 平台：

- 用 Skill 定义 Agent 的工作流程；
- 用 References 保存结构化的领域资料；
- 用混合检索访问大规模知识；
- 用 MCP 访问企业系统和业务工具；
- 用统一权限、审计和评测保障生产可用性。

## 版本路线

| 版本 | 目标 | 主要交付 |
| --- | --- | --- |
| V1 | PDF 问答本地版 | 上传、入库、提问、答案、页码和原文 |
| V2 | 多入口知识库 | 飞书登录、文档接入、增量同步和真实权限 |
| V3 | 只读业务 Agent | Skill 流程、References、获准实时只读查询 |
| V4 | 企业生产版 | 受控云部署、审计、备份恢复、监控、质量与成本治理 |
| V5 | 受控业务办理 | 用户确认、审批、低风险操作、幂等与人工接管 |
| V6 | 集团扩展版 | 多业务域与子公司隔离，按实际瓶颈扩容 |

V4 是企业级知识与只读 Agent 的生产基线。V5 / V6 按业务需要扩展，不要求提前完成；远程试点所需的安全和运维能力必须提前落实。

## 当前阶段

已完成 V1 工程初始化（2.1～2.3）：Next.js 最小首页、TypeScript 严格模式、测试和构建工具链。数据库、PDF、本地模型和问答业务尚未接入，整个 V1 尚未完成。

**接下来开始写功能，先做 PDF 上传和资料列表。** V1 按下面的顺序交付：

1. **上传和资料列表**：上传、保存和删除 PDF，刷新或重启后资料仍在。
2. **读取并保存资料**：查看提取的文字和处理状态，让资料可以搜索。
3. **提问和查看来源**：输入问题，查看答案、文件名、页码和原文。
4. **完整试用检查**：用几份 PDF 检查从上传到问答的完整流程。

数据库接入是为了保存资料，PDF 解析和模型接入是为了读取与搜索资料，不再单独安排一轮架构搭建。本次只调整计划，功能尚未开发；开始每个功能前确认必要的依赖、数据操作和费用范围。

V1 先用 3 份无敏感演示 PDF 和约 10 个基于资料的问题跑通主链路，仅供本机单人使用。真实资料、多用户试点和生产服务分别按后续版本验证，不能把本地演示当成企业上线。

## 技术路线

首版采用 TypeScript 全栈路线，先在本地验证，后续部署到境内阿里云：

- 问答：DeepSeek API，经 Model Gateway 执行策略校验与调用管理。
- 检索：PostgreSQL + pgvector，应用侧中文分词与向量召回后使用 RRF 排序融合。
- 向量生成：本地中文 Embedding，首期不部署独立语义重排序模型。
- 文件：本地受控存储，后续通过适配器接入阿里云 OSS。

应用框架已确认采用 Next.js，同仓库的本地计算进程将在后续获准阶段实现。中文召回效果和本地模型资源需求仍需验证；本地运行也不免除 DeepSeek API 外发数据的合规要求，严格受限内容禁止发送给外部模型。

## 本地运行

以下命令在仓库根目录执行，当前运行脚本面向本机 macOS。使用已有 nvm 和 Node 24.11.0，不修改全局默认版本：

```bash
nvm use
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

`corepack pnpm` 使用 `package.json` 指定的 pnpm 10.10.0；已有该版本的 `pnpm` 时可直接使用。缺少 Node 时先确认安装范围，不自动升级其他环境。

打开 `http://127.0.0.1:3000`。首页显示初始化完成和未接入能力，不代表数据库健康检查或 PDF 问答已经可用。服务仅监听回环地址，不用于远程访问；按 `Ctrl+C` 停止。

类型检查、代码检查和单次测试：

```bash
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm test
```

生产运行（先停止开发服务，避免占用同一端口）：

```bash
corepack pnpm build
corepack pnpm start
```

生产模式仍访问 `http://127.0.0.1:3000`，按 `Ctrl+C` 停止。`typecheck` 会生成框架类型后运行 `tsc --noEmit`，不要求先构建；生成的 `next-env.d.ts`、`.next/` 不提交。

本阶段不需要 `.env.local` 或任何密钥。`.env.example` 只提供空示例，尚无读取数据库 / 模型配置的代码。真实凭据只允许放在本地环境文件，禁止使用 `NEXT_PUBLIC_` 前缀；本地环境文件被 Git 忽略。启动、构建及类型生成脚本默认关闭 Next.js 遥测，不使用远程字体、图片或分析服务。

常见问题：端口占用时先确认占用进程，不自动终止其他应用；`start` 缺少构建产物时先运行 `build`；Node 版本不符时运行 `nvm use`，不降低版本约束或绕过锁文件。

## 初始化验收

5 个页面测试从缺少首页的失败结果到全部通过；类型检查、零警告 lint 和生产构建通过。开发 / 生产首页通过 Chrome 浏览器验证：标题和内容正确、无框架错误界面、无相关控制台错误；页内范围导航可用。桌面与 390px 移动视口布局已检查，无横向溢出。开发和生产服务的实际监听地址均为 `127.0.0.1:3000`。

验证服务交付前停止，不保持后台运行。数据库集成、PDF 解析、本地向量和真实 API 测试未运行，将在对应功能中按获准范围验证。原工程初始化的详细记录保留在 [V1 功能计划](docs/plans/2026-11-07-v1-engineering-compatibility.md) 的折叠区。

## 协作约定

核心 AI 规范：[agent.md](agent.md)。重要技术决策必须先分析场景，提供方案优劣、阶段适用性、验证证据与迁移代价的对比，再由用户确认；长期架构演进按实际瓶颈和复审条件推进，不默认提前升级。

本项目遵循“先确认计划，再按指定功能执行”的协作方式。后续计划先讲“做什么、你能看到什么、怎么确认完成、下一步”，保持简短；技术细节放在后面或折叠区。每完成一个功能，都要同步更新计划文档、验证结果和待办事项。
